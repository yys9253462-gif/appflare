[appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-browser-install-install-1) 会把 Appflare 安装到你自己的 Cloudflare 账户中。登录 Cloudflare，选择账户、名称和地址后，页面会部署 Appflare，并在该地址打开它，供你创建所有者账户。无需创建 API 令牌，不涉及 Git 账户，也不用在电脑上安装软件。

网页本身无法创建 Worker，因为 Cloudflare API 不接受来自网页的这类请求。实际部署由页面背后的 Appflare 托管安装器完成，它是一个小型开源服务，在安装的几分钟里能够操作你的账户。[安装器会看到并保存什么](#what-the-installer-sees-and-keeps)详细解释了其中的含义。如果你不希望 Appflare 的任何服务访问账户，请选择[其他安装方式](/start/install/#which-way-to-choose)。

## 开始前 [#before-you-start]

- **Cloudflare 账户。** Workers 免费套餐即可。
- **Appflare 的访问地址。** 可以是账户中状态为 **Active** 的域名，也可以是 `workers.dev` 子域名。如果两者都没有，首次在 Cloudflare 控制台打开 **Workers & Pages** 时会获得一个 `workers.dev` 子域名。
- **至少一个空闲的定时触发器。** Appflare 的定时更新检查需要一个触发器。免费账户共有五个。如果全部占用，部署仍会完成，Appflare 也可以使用，但页面会提示更新检查等例行检查无法自动运行。释放其他 Worker 的一个触发器即可开启这些检查。
- **允许 appflare.dev 保存站点数据且开启 JavaScript 的浏览器。** 隐私窗口经常拒绝保存站点数据，此时页面无法完成登录。

如果账户管理员在 Cloudflare 控制台的 **Manage Account > Members > Settings** 中关闭了 **Public OAuth App access**，Cloudflare 会拒绝 Appflare 等应用的新登录授权。请改用 [Cloudflare 部署按钮](/start/deploy-button/)或[命令行](/start/install/#advanced-install-from-the-command-line)。

## 安装步骤 [#install]

页面顶部会显示连接、账户、名称、地址、确认、部署和设置等步骤。在确认页选择**部署 Appflare**之前，不会在你的账户中创建任何资源。

### 1. 连接 Cloudflare [#1-connect-cloudflare]

选择**连接 Cloudflare**。Cloudflare 会要求你登录、选择 Appflare 可以访问的账户，并允许所需权限。请允许全部权限。Appflare 一次申请其使用的所有权限，因此以后开启新功能时无需再次申请；如果缺少任何权限，它会拒绝接受这次登录。页面中的 **Appflare 请求的权限**列出了完整清单。

这些权限与其他安装方式使用的 [API 令牌](/start/install/#1-connect-cloudflare)相同，但不包含 Billing：Cloudflare 不向这种登录方式的应用提供 Billing 权限。Appflare 会根据账户可用功能推断 [Workers 套餐](/guides/install-apps/#workers-free-or-workers-paid)，或者由你在设置中选择。

Cloudflare 会把你送回 appflare.dev，由浏览器完成登录。

### 2. 选择账户 [#2-choose-the-account]

如果你的登录可以访问多个账户，请选择 Appflare 要安装到的账户；只有一个账户时会跳过这一步。如果账户里有未完成的安装，页面会先列出它们。请参阅[继续或移除未完成的安装](#continue-or-remove-an-unfinished-installation)。

### 3. 设置名称 [#3-name-it]

默认名称是 `appflare`。Appflare 的 Worker 和 D1 数据库使用这个名字，KV 命名空间叫 `<name>-kv`，Workflow 叫 `<name>-jobs`。名称只能包含小写字母、数字和短横线。如果账户里还没有 Appflare，保留建议值即可；已被占用的名称会被拒绝。

### 4. 选择访问地址 [#4-choose-its-address]

你会在这个地址打开 Appflare 并登录，通行密钥也绑定到该地址，因此请选一个你希望长期使用的地址。

- **使用自己的域名。** 页面建议 `appflare.<your domain>`。可以修改前面的部分，或选择账户中的另一个域名。Cloudflare 会创建 DNS 记录和证书。
- **使用 Cloudflare 免费地址**：`https://<name>.<your subdomain>.workers.dev`。

继续之前，页面会检查你的域名名称。如果已有 DNS 记录（覆盖它的通配记录也算）、已绑定到其他 Worker，或被 Workers 路由覆盖，就会拒绝使用，避免覆盖现有服务。请换一个名称，或先释放这个名称。

以后也可以迁移 Appflare 的地址；请参阅[为 Appflare 配置专用地址](/guides/appflare-address/)。

### 5. 部署前确认 [#5-check-before-you-deploy]

确认页会显示账户、名称、完整地址，以及已通过签名校验的最新 Appflare 发布版本。**创建位置**会列出此次安装将创建的全部资源：

- 以你选择的名称命名的 Worker；
- 它的 D1 数据库和 KV 命名空间；
- 它的 Workflow，以及每 5 分钟执行一次的计划；
- 带 DNS 记录和证书的自定义域名，或 `workers.dev` 地址。

账户中已经存在的内容不会被更改。确认后选择**部署 Appflare**。

### 6. 部署 [#6-deploy]

进度条会逐一显示步骤：检查发布版本、创建数据库和键值存储、上传 Appflare 文件与管理器本身、配置后台任务、安排定时检查、保存设置密钥、启用 `workers.dev` 地址、连接域名，以及等待 Appflare 响应。安装器在上传任何内容之前，会验证发布版本的 Ed25519 签名和每个文件的 sha256。

运行期间可以关闭标签页。安装进度会被保留；以后在同一个浏览器重新打开 [appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-browser-install-install-2)，再次连接 Cloudflare 后，页面会继续安装。如果浏览器不允许页面记住安装信息，页面会明确提示，此时请保持标签页打开直到结束。

最后一步会等待新 Appflare 在所选地址响应，并证明它属于这次安装。仅仅有网页响应还不够；在地址证明身份之前，不会向它发送任何凭据。

### 7. 交接并打开 Appflare [#7-hand-over-and-open-appflare]

页面会再次检查地址，然后直接从浏览器把 Cloudflare 连接交给新安装的 Appflare。Appflare 会立即续期连接，使浏览器持有的副本失效，此后只有 Appflare 能继续续期。页面会显示 **Appflare 已就绪**，并打开它的地址。

### 8. 创建所有者账户 [#8-create-the-owner-account]

由于页面已经连接了 Cloudflare，Appflare 会直接打开[设置向导](/start/install/#the-setup-wizard)中的所有者步骤。输入名称、邮箱和至少 12 个字符的密码，然后[检查账户](/start/install/#3-check-your-account)，选择**完成**。

如果 Appflare 已在你的域名上运行，会跳过 **Appflare 应该放在哪里？**，因为它已经在那里了。若运行在 `workers.dev`，而账户中有已激活域名，向导会提供迁移选项。

打开所有者步骤的链接只能使用一次，有效期 30 分钟。如果页面提示**这个设置链接已失效**，请在原安装浏览器中重新打开 [appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-browser-install-install-3)，连接 Cloudflare，然后选择**继续**。页面会使用新的链接打开 Appflare。

如果有人先在另一个浏览器打开你的新 Appflare，他们会看到**请回到安装 Appflare 的地方完成设置**，不能创建所有者。同一页面也提供**改用 API 令牌连接**，任何能为账户创建令牌的人都能使用；这样的人本来就拥有账户控制权。

所有者创建完成后，Appflare 会通知安装器，安装器随即删除本次安装记录。

## 紧接着安装应用 [#install-an-app-right-after]

在 appflare.dev 的应用页面选择**安装**时，如果浏览器还不知道你的 Appflare 地址，可以选择**获取 Appflare**，再选择**安装 Appflare**。它会以 `appflare.dev/deploy/?app=<slug>` 打开部署页，提示你所选应用会在 Appflare 设置完成后打开。安装步骤相同。

Appflare 就绪后，页面会打开设置向导，并在后面保留该应用的[安装链接](/guides/install-links/)。创建所有者并选择**完成**，新 Appflare 就会打开该应用页面，等待安装。如果 Appflare 已有所有者，**在 Appflare 中打开应用**会在登录后直接打开该应用页面。

登录 Cloudflare 期间，页面仅在当前标签页保存所选应用，并在返回时继续使用它。不带 `?app=`，或参数不是有效应用时，只安装 Appflare。如果关掉标签页之后再继续，请在 Appflare 设置完成后重新点击应用的**安装**按钮。

页面也会像[在 appflare.dev 上使用你的 Appflare](/guides/install-links/#use-your-appflare-on-appflaredev)一样，在这个浏览器记住新 Appflare 的地址，此后 appflare.dev 的安装按钮就会在那里打开应用。

## 如果域名需要等待 [#if-the-domain-takes-a-while]

域名下的新名称需要 DNS 记录和证书就绪后，浏览器才能访问。通常需要一到五分钟，有时更久。等待期间，页面会说明 Cloudflare 正在处理什么，自动重复检查，并提供**立即检查**。它不会自行放弃。

等待 20 秒后，页面还会提供**通过 workers.dev 打开**。选择后，你可以先在 Appflare 的 `workers.dev` 地址用密码创建所有者账户。Appflare 会继续检查域名，域名可用后自行迁移过去。请在域名上用相同邮箱和密码登录；Appflare 会说明已迁移，并提供添加属于该域名的通行密钥的选项。

## 继续或移除未完成的安装 [#continue-or-remove-an-unfinished-installation]

安装器会一直保留未完成的安装，直到创建所有者或手动移除。关闭标签页或放置几天，都不会删除安装记录及已创建的资源。

要继续，请在最初使用的浏览器中打开 [appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-browser-install-install-4)。页面会显示**继续安装 Appflare**。连接 Cloudflare（页面不能自行续期访问，因此通常需要再次授权），然后点击安装旁的**继续**。它会在同一地址从中断处继续，不会重复创建部署。

页面会在账户下列出其他浏览器中开始的安装。只有发起安装的浏览器能够继续，因为只有它持有安装密钥。但任何能登录并访问该 Cloudflare 账户的浏览器，都可以移除安装。

要移除，请选择旁边的**移除…**，或失败步骤后的**移除此安装…**。页面会列出将删除的内容，即安装截至中断时创建的资源。账户中原先存在的内容保持不变。Appflare 数据随数据库一起删除，无法撤销。移除完成后，安装器删除安装记录。

已有所有者的 Appflare 不再属于未完成安装，请按[移除 Appflare](/guides/danger-zone/#remove-appflare-from-this-account)中的说明，从它自己的设置页移除。

### 某一步失败时 [#when-a-step-fails]

**部署已停止**会显示失败步骤和 Cloudflare 给出的原因。如果指出了原因，请先修复，再选择**重试**，安装会从该步骤继续。

**Appflare 已部署，但尚未连接**表示部署成功了，但交接没有完成。消息会说明原因。最常见的情况是新 Appflare 尚未响应，或有人在另一个浏览器用 API 令牌完成设置。**重试**是安全的：没有证明属于你的地址不会收到连接。如果页面提示 Cloudflare 连接已到期或不被接受，请再次连接 Cloudflare，选择安装所在账户，并允许全部权限。

## 安装器会看到并保存什么 [#what-the-installer-sees-and-keeps]

- **它会收到短期访问令牌。** 页面发给安装器的每个请求都携带连接 Cloudflare 时签发的访问令牌。令牌约一小时有效，拥有你允许 Appflare 的全部权限，远多于部署所需。在有效期内，安装器理论上可以在你选择的账户里执行这些权限允许的任何操作。安装器实际只用它部署 Appflare，不保存也不记录令牌。但丢弃令牌不等于在 Cloudflare 撤销它，它会一直有效直到过期。
- **它永远不会收到刷新令牌**，也就是之后维持 Appflare 连接的那部分。浏览器直接把刷新令牌交给新 Appflare 后便遗忘它，Appflare 会立即续期。这描述的是公开代码的行为。运行其他代码的安装器不能从浏览器直接取得刷新令牌，但在访问令牌有效期内，它可以做部署之外的事情，例如修改正在部署的 Appflare。这就是下文所说的信任。
- **它会保留安装记录**直到设置完成：你的 Cloudflare 账户 id、名称、地址、Appflare 发布版本、已创建资源的 id 和当前进度。不含令牌、密码、所有者信息或应用信息。记录没有保留期限；创建新 Appflare 的所有者账户，或移除未完成安装后才会删除。
- **代码开源**，位于 Appflare 仓库的 [apps/installer](https://github.com/appflare/appflare/tree/main/apps/installer)，你可以阅读它如何使用令牌。但你无法验证 appflare.dev 实际运行的是否就是同一份代码。使用它意味着选择信任这个服务。

部署页及 Cloudflare 返回的页面不会运行其他分析，仅统计每次安装进行到哪一步，不包含你或账户的信息。请参阅[隐私](/privacy/#installing-appflare-from-this-site)。

Appflare 获得连接后，就会自行与 Cloudflare 通信。即使 appflare.dev 不可用，你的 Appflare 和应用仍会工作。之后还有两件事会经过 appflare.dev：从 Appflare 设置里再次用 Cloudflare 登录时，会回到该站点的页面，并使用 Appflare 在 Cloudflare 注册的客户端。API 令牌不需要这两项；请参阅 [Appflare 的 Cloudflare 连接](/guides/cloudflare-connection/)。

要让所有 Appflare 服务都不接触你的账户，请通过[Deploy to Cloudflare 按钮](/start/deploy-button/)或[安装器](/start/install/)安装。它们使用你自行创建的 API 令牌，令牌从 Cloudflare 控制台直接进入你的 Appflare，不经过其他地方。

## 安装完成后 [#afterwards]

Appflare 使用 Cloudflare 登录连接，并自行续期。如果 Cloudflare 不再接受连接，管理员会看到**重新连接 Cloudflare**。要改用 API 令牌或撤销 Appflare 的访问，请参阅 [Appflare 的 Cloudflare 连接](/guides/cloudflare-connection/)。
