Appflare 是面向 Cloudflare 的自托管应用管理器。把它安装到你自己的 Cloudflare 账户后，它只需一个 Worker 就能运行。你可以在网页界面中浏览为 Workers 构建的应用，将它们安装到同一账户，并持续更新。首页会显示已安装的应用和需要你处理的事项。

![首页显示待审核更新、按应用统计的账户用量，以及已安装应用和各自用量](/screenshots/home-dashboard.png)

## 工作原理 [#how-it-works]

无论采用哪种安装方式，都会在你的 Cloudflare 账户中部署一个管理器 Worker。它的网页界面提供了可在 Workers 上运行的应用目录。

安装应用时，管理器会创建并记录该应用需要的资源：KV 命名空间、D1 数据库、R2 存储桶、队列、Vectorize 索引、密钥和定时触发器。因为它知道自己创建了哪些资源，之后就能更新应用、回滚版本，并完整地移除应用。

目录中的每个应用都由目录的 CI 从固定的上游提交构建、打包并签名。签名校验不通过的内容，管理器一律不会安装。

## 为什么需要 Appflare [#why-it-exists]

Cloudflare 的“Deploy to Cloudflare”按钮会把应用仓库复制到你的 GitHub 账户。副本与原仓库没有关联，因此你不会收到新版本通知，也没有现成的更新方式。

Appflare 则负责管理安装本身。它记录为应用创建的每个资源，因此可以更新、回滚和卸载应用。Appflare 自身也能通过该按钮安装，因为之后它会自行更新，不再需要那份副本。

## 使用边界 [#what-it-is-not]

- **不提供托管服务。** 所有内容都运行在你的账户中，使用你的套餐并受你的额度限制。没有其他人为你运行服务器。
- **不是模板合集。** 应用会被实际安装并运行，而不是复制成一个之后要由你维护的仓库。
- **与 Cloudflare 没有隶属关系。** Appflare 是独立开源项目，不受 Cloudflare, Inc. 背书或赞助。
- **不收集个人数据。** Appflare 会发送匿名报告（数量、版本和错误类别，不包含你的账户、邮箱、域名或密钥），帮助确定开发和修复重点。默认开启，也很容易关闭；请参阅[匿名报告](/telemetry/)。安装器执行命令时也会关闭 wrangler 自身的用量统计。

## 会安装哪些资源 [#what-gets-installed]

无论采用哪种方式，都会在账户中创建以下资源：

| 资源 | 名称 |
| --- | --- |
| Worker | `appflare`，访问地址为 `https://appflare.<your-subdomain>.workers.dev` |
| D1 数据库 | `appflare` |
| KV 命名空间 | `appflare-kv`（部署按钮方式则使用项目名称） |
| Workflow | `appflare-jobs` |
| 定时触发器 | 每 5 分钟执行一次 |
| 自定义域名 | 仅当你在设置期间或之后为 Appflare [配置专用地址](/guides/appflare-address/)时创建 |

D1 数据库保存用户、设置、安装记录和任务日志。KV 命名空间缓存应用目录。Workflow 以持久任务的方式执行安装、更新、回滚和卸载。定时触发器每 5 分钟读取各应用的[用量](/guides/spend-protection/)，每 30 分钟刷新目录并检查新版本。只有开启[自动更新](/guides/updates/#automatic-updates)后，它才会自行启动更新任务。

## 项目组成 [#the-parts]

- **管理器**是上面所说的 Worker，以及它的网页界面。
- **部署页** [cf.hejige.com/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-overview-install-2) 负责将管理器安装到你的账户。Cloudflare 的部署按钮和命令行安装器 `create-appflare` 也能完成这件事。
- 安装之后的所有操作，包括更新和移除，都在管理器的设置页进行。
- **应用目录**是公开的 GitHub 仓库 `yys9253462-gif/appflare-catalog`。它的 CI 从固定提交构建每个应用，签名后发布。请参阅[目录工作原理](/catalog/how-it-works/)。
