## 通过浏览器安装 [#install-from-your-browser]

<InstallButton placement="install-primary" />

推荐使用这种方式。打开 [appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-install-install-1)，登录 Cloudflare，选择账户和 Appflare 的地址，页面就会在那里部署 Appflare。你只需要能登录 Cloudflare：无需 API 令牌、Git 账户，也不用在电脑上安装软件。[通过浏览器安装](/start/browser-install/)提供了逐步说明。

也可以使用 Cloudflare 部署按钮。它会先在你的 GitHub 或 GitLab 账户中创建 Appflare 副本，安装后需要清理。[使用部署按钮安装](/start/deploy-button/)介绍了完整过程。

[Cloudflare 部署按钮](https://link.appflare.dev/deploy-1c?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-install-cloudflare-1)

所有方式都会把同一个已签名发布版本部署到你的账户，最后进入相同的[设置向导](#the-setup-wizard)。

| | 浏览器安装 | Cloudflare 部署按钮 | 命令行 |
| --- | --- | --- | --- |
| 操作方法 | 打开 [appflare.dev/deploy](https://cf.hejige.com/deploy/?utm_source=appflare-docs&utm_medium=website&utm_campaign=appflare&utm_content=start-install-install-2) | 点击按钮，参阅[使用部署按钮安装](/start/deploy-button/) | 运行 `npx create-appflare`，参阅下方[高级安装](#advanced-install-from-the-command-line) |
| 前置条件 | 可登录 Cloudflare | GitHub 或 GitLab 账户 | Node.js 22 |
| Appflare 的连接方式 | 页面配置的 Cloudflare 登录授权 | 设置过程中自行创建的 API 令牌 | 设置过程中自行创建的 API 令牌 |
| 安装期间谁会访问账户 | Appflare 托管安装器，使用短期令牌 | Cloudflare Workers Builds | Wrangler，使用你的登录凭据 |
| 安装后残留 | 设置完成后无残留 | Git 账户中的 Appflare 副本和 Workers Builds 连接，需要清理 | 无 |

### 如何选择 [#which-way-to-choose]

- **浏览器安装**步骤最少，除非符合下面的特殊情况，否则建议使用。部署之前就能选择 Appflare 的地址，因此首次访问就可以在该地址登录并添加通行密钥。代价是信任：安装的几分钟内，Appflare 的托管安装器会持有一枚能执行 Appflare 全部操作的令牌。[安装器会看到并保存什么](/start/browser-install/#what-the-installer-sees-and-keeps)对此作了说明。
- **Cloudflare 部署按钮**适合不希望任何 Appflare 服务接触账户、且拥有 GitHub 或 GitLab 账户的用户。安装后需要清理仓库副本。Appflare 最初运行在 `workers.dev`；设置向导的 **Appflare 应该放在哪里？** 步骤可以把它迁移到你的域名，然后你需要在新地址重新登录。
- **命令行**用于前两种方式都不适用的少数情况。

无论选择哪一种，以后都可以改变 Appflare 与 Cloudflare 的连接方式；请参阅 [Appflare 的 Cloudflare 连接](/guides/cloudflare-connection/)。

## 高级：从命令行安装 [#advanced-install-from-the-command-line]

<details>
<summary>使用 `npx create-appflare` 安装</summary>

当 Cloudflare 账户不允许登录第三方应用时，可以使用这种方式。账户管理员可以禁止公开 OAuth 应用，此时浏览器安装无法完成登录。

### 前置条件 [#requirements]

- 安装所用电脑上有 **Node.js 22 或更新版本**。
- **Cloudflare 账户。** Workers 免费套餐可用；目录中部分应用要求更高，会在各自页面说明。
- 账户中有 **`workers.dev` 子域名**。如果没有，wrangler 会在安装时询问是否注册，这需要终端交互；否则请先在 Cloudflare 控制台注册。
- 有权为账户**创建 API 令牌**。账户级令牌需要 Super Administrator 角色；其他成员可使用用户令牌。

### 运行安装器 [#run-the-installer]

```sh
npx create-appflare
```

#### 从源码运行 [#from-a-checkout]

如果要从仓库源码运行安装器，需要 Node.js 22 和 pnpm：

```sh
git clone https://github.com/appflare/appflare
cd appflare
pnpm install
pnpm --filter "create-appflare..." build
node packages/cli/bin/appflare.js
```

在源码目录运行的 `node packages/cli/bin/appflare.js`，支持与 `npx create-appflare` 相同的选项。

#### 安装器会做什么 [#what-the-installer-does]

1. 检查 Node.js 版本和 Cloudflare 登录状态。若 wrangler 尚未登录，会在浏览器打开 `wrangler login`。如果登录可访问多个账户，会询问选择哪个；可设置 `CLOUDFLARE_ACCOUNT_ID` 跳过选择。
2. 如果已有名为 `appflare` 的 Worker、名为 `appflare` 的 D1 数据库，或名为 `appflare-kv` 的 KV 命名空间，就拒绝继续。
3. 从 [github.com/appflare/appflare/releases](https://github.com/appflare/appflare/releases) 下载最新管理器版本。它会用安装器内置公钥验证 Ed25519 签名，并校验每个文件的 sha256。所有校验通过后才部署。
4. 从临时目录通过 `wrangler deploy` 部署管理器。Wrangler 会创建 D1 数据库和 KV 命名空间。
5. 为管理器设置随机密钥 `BETTER_AUTH_SECRET`，用于签发会话。
6. 等待管理器响应，然后输出地址 `https://appflare.<your-subdomain>.workers.dev/`。打开它以完成设置。该地址不含密钥。

结束时会删除临时目录。不会向当前目录写入内容，也不会创建 Git 仓库。

#### 选项 [#options]

| 参数 | 含义 |
| --- | --- |
| `--version <x.y.z>` | 安装指定管理器版本，而非最新版。 |
| `--name <name>` | Worker 名称，默认为 `appflare`；D1 数据库和 KV 命名空间会跟随命名。 |
| `-y`, `--yes` | 不询问。遇到必须询问的情况就失败：多个账户、没有 `workers.dev` 子域，或 Workflow 名称已属于其他 Worker。 |
| `--artifact-dir <dir>` | 从 `<dir>` 中已下载的发布包安装，不再获取远端版本。仍要求有效签名。 |
| `--no-telemetry` | 不发送[匿名使用数据](/telemetry/)，并关闭所安装管理器的匿名报告。 |
| `-v`, `--version` | 输出安装器版本；`--version` 后跟数值时则用于选择管理器版本。 |
| `-h`, `--help` | 输出选项说明。 |

若下载触发 GitHub 限流，请设置 `GITHUB_TOKEN`。安装器只会将它发送到 `api.github.com`。

如果部署后安装失败，安装器会输出用于删除已创建资源的 `wrangler` 命令，便于清理后重试。

安装器只负责安装。管理器运行后，请在其设置页中管理。安装器输出各页面地址时，会在路径前加上管理器的完整地址：

| 目的 | 入口 |
| --- | --- |
| 查看运行版本并更新 Appflare | **设置 → 更新 → Appflare 版本**（`/settings/updates#appflare`）。参阅[更新 Appflare](/guides/update-appflare/)。 |
| 返回早期管理器版本 | **设置 → 更新 → 最近版本**（`/settings/updates#versions`）。参阅[回滚](/guides/update-appflare/#roll-back)。 |
| 启用、更新或关闭沙盒构建 | **设置 → 构建应用 → 在账户中构建**（`/settings/building#sandbox`）。参阅[沙盒构建](/guides/builds/)。 |
| 移除 Appflare 及其数据 | **设置 → 账户 → 危险区**中的**移除 Appflare**（`/settings/account#danger-zone`）。参阅[移除 Appflare](/guides/danger-zone/#remove-appflare-from-this-account)。 |

</details>

## 设置向导 [#the-setup-wizard]

打开管理器地址。在设置完成之前，管理器的所有页面都会进入设置向导：同一个页面中依次呈现三个步骤；账户有已激活域名时为四步。

通过[浏览器安装](/start/browser-install/)后，安装页面已经替你完成第 1 步，会直接打开第 2 步。其他浏览器首次访问该 Appflare 时会看到**请回到安装 Appflare 的地方完成设置**，也可以选择**改用 API 令牌连接**在此完成第 1 步。

### 1. 连接 Cloudflare [#1-connect-cloudflare]

管理器需要 Cloudflare API 令牌，才能在账户中创建和更新应用。Cloudflare 不允许 Worker 或 wrangler 创建这种令牌，因此要在控制台完成：

1. 选择**创建令牌**。控制台会打开名为 `Appflare` 的账户级令牌表单，并预先勾选下表权限，无需逐项选择。选择账户，向下滚动，依次点击 **Review token** 和 **Create token**，然后复制令牌。若不是 Super Administrator，请使用**改为创建用户令牌**。设置页的**令牌能做什么**列出每项权限及使用它的功能。
2. 粘贴令牌。
3. 选择**继续**。管理器会一次性检查令牌是否有效、能否管理 Workers，以及是否属于管理器所在账户（它会在令牌的账户中查找当前提供页面的自身版本），随后保存并显示已连接账户。无法确认的权限会提示警告；被拒绝的令牌会当场显示原因。

令牌是设置阶段唯一的保护。能为账户创建令牌的人本来就控制着该账户，因此没有单独的设置密码。其他账户的令牌会被拒绝，并显示其所属账户。每个网络地址在 10 分钟内最多尝试 20 次。

### 2. 创建所有者账户 [#2-create-the-owner-account]

输入名称、邮箱和至少 12 个字符的密码。首位用户是所有者：既是管理员，也是唯一可以修改角色、删除用户或移交所有权的人。创建后会立即登录。

账户有已激活域名时，接下来会询问 **Appflare 应该放在哪里？**：保留 `workers.dev` 地址，或迁移到自有域名下的某个名称。选择**稍后**可跳过。请参阅[为 Appflare 配置专用地址](/guides/appflare-address/)。

只有保存令牌的浏览器才能在之后 30 分钟内完成这一步。此时其他浏览器打开管理器只会看到第 1 步；所有者创建后则显示登录页。如果完成这一步前关掉浏览器，请在 30 分钟后重新打开管理器并再次粘贴令牌。浏览器安装时，部署页带过来的浏览器持有这一步的权限；如果链接失效，请参阅[创建所有者账户](/start/browser-install/#8-create-the-owner-account)。

### 3. 检查账户 [#3-check-your-account]

管理器会读取应用所依赖的 Cloudflare 账户功能。进度条显示当前套餐支持的项目中，有多少已就绪。每行列出功能、应用需要它的原因，以及状态：

- **就绪**：账户已具备该功能。
- **需要处理**：功能关闭，而已安装或正在安装的应用需要它。
- **未配置**：功能关闭，但当前没有应用需要它。等你要安装的应用需要时再开启。
- **仅限付费套餐**：只在 Workers Paid 中提供。
- **无法检查**：Appflare 无法读取。选择**重新检查**。

![账户设置中完整的就绪进度条和各项账户检查](/screenshots/settings-account-capabilities.png)

未开启项目有一个操作按钮：**在 Cloudflare 中开启**会打开对应控制台页面；**在 Cloudflare 中编辑令牌**会打开令牌页面；**选择套餐**让你在 Appflare 无法读取时指定 Workers 套餐；**配置**会打开**设置 → 构建应用 → 在账户中构建**。**详情**显示检查结果、检查时间、无法确定时的错误，以及有多少目录应用用到它。

| 项目 | 用途 |
| --- | --- |
| Workers 套餐 | Workers Paid 提高免费套餐的限额并支持容器；部分应用需要它。 |
| workers.dev 地址 | 除非配置自有域名，否则每个应用都会通过各自的 `workers.dev` 地址响应。 |
| R2 存储 | 保存应用文件和上传内容。开启免费，但 Cloudflare 会先要求添加付款方式。 |
| 域名 | Cloudflare 上的域名，用于[自定义域名](/guides/custom-domains/)和[接收邮件的应用](/guides/email-apps/)。 |
| 邮件路由 | 将域名的邮件投递给应用。安装此类应用时会开启。 |
| Analytics Engine | 保存页面浏览和链接点击等应用统计事件。首次在控制台打开其页面前保持关闭；写入它的应用在此之前无法安装。 |
| Zero Trust | 在管理器或应用前使用 [Cloudflare Access](/security/#protect-with-cloudflare-access) 设置登录保护之前，需要先配置。 |
| 沙盒构建 | 在账户内构建没有现成发布版本的应用。仅限付费套餐，需要 Workers Paid、已开启 R2 和 Containers 权限。第一个需要构建的应用会开启它；也可通过**配置**提前开启。 |
| 令牌权限 | 检查 Appflare 令牌是否具备所需权限。**详情**会指出缺少的可选权限。 |

新账户的大多数项目显示**未配置**是正常现象。只有**需要处理**的项目会妨碍已安装的应用使用。

在控制台更改后，选择**重新检查**。选择**完成**进入管理器。相同列表也会保留在**设置 → 账户 → 这个账户能运行什么**中。

令牌模板请求以下权限：

| 权限 | 访问级别 | 用途 |
| --- | --- | --- |
| Workers Scripts | 编辑 | 上传、部署和删除应用 Worker 与管理器本身，包含其密钥、定时触发器、路由和静态资源。 |
| Workers KV Storage | 编辑 | 为绑定 KV 的应用创建 KV 命名空间。 |
| D1 | 编辑 | D1 数据库、应用迁移和 Time Travel 还原。 |
| Workers R2 Storage | 编辑 | 为绑定 R2 的应用创建 R2 存储桶。 |
| Queues | 编辑 | 为使用队列的应用创建队列。 |
| Vectorize | 编辑 | 为绑定 Vectorize 的应用创建索引。 |
| Account Settings | 读取 | 查找令牌所属账户。 |
| Access: Apps and Policies | 编辑 | 仅用于 Cloudflare Access：创建、更新和删除保护管理器（[使用 Cloudflare Access 保护](/security/#protect-with-cloudflare-access)）或已安装应用的 Access 应用和策略。 |
| Access: Organizations, Identity Providers, and Groups | 读取 | 仅用于 Cloudflare Access：读取 Zero Trust 组织的团队域名和登录方式。 |
| Access: Service Tokens | 编辑 | 仅用于通过 Cloudflare Access 保护已安装应用：每个受保护应用有自己的服务令牌，仅供 Appflare 健康检查使用。Appflare 会创建它、在到期前续期，并在应用不再受保护或卸载时删除。 |
| Zone | 读取 | 仅用于[自定义域名](/guides/custom-domains/)、[外部域名](/guides/external-domains/)和[接收邮件的应用](/guides/email-apps/)：列出域名。外部域名需要账户所有区域的此权限，以判断主机名是否属于自有域名。 |
| DNS | 编辑 | 仅用于[自定义域名](/guides/custom-domains/)：查看新主机名的 DNS 记录，并在你同意后替换；用于[外部域名](/guides/external-domains/)：添加网关 DNS 记录；用于[接收邮件的应用](/guides/email-apps/)：启用邮件路由前读取 MX 记录。 |
| Workers Routes | 编辑 | 仅用于[自定义域名](/guides/custom-domains/)：将应用 Worker 绑定到主机名；用于[外部域名](/guides/external-domains/)：把网关域名请求路由到网关 Worker。 |
| SSL and Certificates | 编辑 | 仅用于[外部域名](/guides/external-domains/)：在网关域名上添加和移除 Cloudflare for SaaS 自定义主机名，并设置备用源站。 |
| Zone Settings | 编辑 | 仅用于[接收邮件的应用](/guides/email-apps/)：开启域名邮件路由，并在卸载时关闭。 |
| Email Routing Rules | 编辑 | 仅用于[接收邮件的应用](/guides/email-apps/)：创建和删除路由规则并设置 catch-all。 |
| Email Routing Addresses | 读取 | 仅用于[接收邮件的应用](/guides/email-apps/)：显示已验证的目标地址。 |
| Billing | 读取 | 仅用于识别账户的 [Workers 套餐](/guides/install-apps/#workers-free-or-workers-paid)：列出账户订阅并读取套餐名称，不读取账单或付款详情。 |
| Hyperdrive | 编辑 | 仅用于[使用外部数据库的应用](/guides/install-apps/#apps-with-a-database-elsewhere)：根据安装时输入的连接字符串创建 Hyperdrive 配置，修改字符串时替换，卸载时删除。 |
| Pipelines | 编辑 | 仅用于[流式写入事件的应用](/guides/install-apps/#apps-that-stream-events)：为每条事件流创建 Pipelines stream、sink 和 pipeline，卸载时删除。 |
| Workers R2 Data Catalog | 编辑 | 仅用于[流式写入事件的应用](/guides/install-apps/#apps-that-stream-events)，且需要手动添加（模板链接无法勾选）：卸载并删除存储桶时移除其 R2 Data Catalog。缺少此权限时仍会删除存储桶。 |
| Account Analytics | 读取 | 仅用于[用量与花费保护](/guides/spend-protection/)：读取各应用的 Workers、存储及其他服务用量，显示用量、发送所配置的用量提醒，并暂停用量失控的应用。 |

标记为“仅用于”的权限是可选的。如果不使用对应功能，可以在表单中移除这些权限，其余功能不受影响。

### 令牌保存在哪里 [#where-the-token-lives]

管理器通过 Cloudflare API，把令牌作为加密密钥 `CF_API_TOKEN` 保存在自己的 Worker 上。保存会重新部署管理器，需要几秒。令牌不会再次显示，不会写入数据库，也不会出现在日志里。请参阅[安全模型](/security/)。

以后要替换令牌，请打开**设置 → 账户 → Cloudflare 连接**，选择**更改 Appflare 的连接方式**，再选择**使用新的 API 令牌**。新令牌必须属于同一账户。之后在 Cloudflare 控制台撤销旧令牌。同一入口也可切换到 Cloudflare 登录方式，一次性授予 Appflare 使用的除 Billing 外的全部权限。请参阅 [Appflare 的 Cloudflare 连接](/guides/cloudflare-connection/)。
